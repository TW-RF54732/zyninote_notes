## 資料與資訊 {#q-data-information}

「資料」與「資訊」有何不同？以「算全班 60 人平均身高」為例說明。

### 詳解 {#q-data-information-solution .fold}

**思路**：處理之前的叫資料，處理之後、對人有用的叫資訊。

- **資料**：還沒處理的原始內容 → 60 筆身高數值。
- **資訊**：資料經過整理、計算後，能拿來參考或做決定的結果 → 全班平均身高。

見 [[ch1-intro#data-information|資料與資訊]]。

## 平均身高的演算法 {#q-height-algorithm}

延續「算全班 60 人平均身高」：用虛擬語言寫出演算法，並說明輸入資料最適合用什麼資料結構。

### 詳解 {#q-height-algorithm-solution .fold}

**思路**：平均 = 總和 ÷ 人數。所以先準備一個總和從 0 開始，每讀一個身高就加進去，讀完再除以 60。

```
STEP 1: sum = 0
STEP 2: LOOP 60 times
          a. INPUT height
          b. sum = sum + height
STEP 3: average = sum / 60
STEP 4: OUTPUT average
STEP 5: STOP
```

**資料結構**：60 筆資料型態都一樣（都是身高），筆數也固定 → 用**陣列**最適合。

## 使用者與撰寫者 {#q-user-programmer}

說明應用程式使用者與程式撰寫者的差別。

### 詳解 {#q-user-programmer-solution .fold}

差別在於「用別人寫好的」還是「自己寫」：

- **應用程式使用者**：操作別人寫好的軟體解決問題，例如用 Excel 算平均。
- **程式撰寫者**：針對問題自己寫程式，例如寫 C 程式讀身高算平均。難度較高，但能解決現成軟體做不到的問題。

## 解題流程 {#q-problem-solving}

說明解決問題的流程。

### 詳解 {#q-problem-solving-solution .fold}

五步，順序是「想清楚 → 寫出來 → 讓電腦跑」：

1. 了解問題、找出要處理的資料
2. 找出演算法（解題步驟）
3. 選一種程式語言把演算法寫成程式
4. 編譯或直譯（翻成電腦看得懂的指令）
5. 執行，得到資訊

見 [[ch1-intro#problem-solving|解題流程]]。

## 演算法的定義與特性 {#q-algorithm}

什麼是演算法？有哪五個特性？常見的描述方式有哪兩種？

### 詳解 {#q-algorithm-solution .fold}

**定義**：為了解決某個問題而規劃的一串步驟，照順序做完就能完成任務（像食譜）。

**五個特性**：

| 特性 | 一句話 |
|---|---|
| 輸入 | 可以沒有（**0 個以上**） |
| 輸出 | **至少 1 個** |
| 有限性 | 一定會在有限步驟內結束 |
| 明確性 | 每一步都清楚、不會有兩種解讀 |
| 有效性 | 每一步都做得到，做完能解決問題 |

最容易考：輸入可以 0 個，輸出至少 1 個。

**描述方式**：**虛擬語言**（接近英文的文字）、**流程圖**（圖形）。見 [[ch1-intro#algorithm-criteria|演算法的五個條件]]。

## 用 for 迴圈算 n! {#q-factorial-for}

以 C 語言的 `for` 迴圈計算 $n!$。

### 詳解 {#q-factorial-for-solution .fold}

**思路**：$n! = 1\times2\times\cdots\times n$。準備一個乘積從 **1** 開始（不能從 0，乘了會一直是 0），讓 `m` 從 1 跑到 `n`，每次乘上去。

```c
int n, product = 1;
scanf("%d", &n);
for (int m = 1; m <= n; m++)
    product *= m;
printf("%d! = %d\n", n, product);
```

例：`n = 4` 時，`product` 依序是 1 → 1 → 2 → 6 → 24。

## 影響執行效率的因素 {#q-efficiency-factors}

列舉三種影響程式執行效率的因素。

### 詳解 {#q-efficiency-factors-solution .fold}

這三個都和「程式本身寫得好不好」無關，是「在哪台機器、怎麼翻譯」的問題，所以分析演算法時改用數指令個數（[[ch1-intro#time-complexity|時間複雜度]]）：

1. **CPU 處理速度**：CPU 越快，同一個程式跑越快。
2. **指令集**：同一個程式在 RISC 和 CISC 機器上，翻成的指令不同，時間也不同。
3. **編譯器**：同一台機器、同一種指令集，不同編譯器翻出來的執行檔速度也不同。

## ASCII 與進制 {#q-ascii-bases}

1. `A` 的 ASCII 碼為 1000001，`B` 為何？
2. 8 位元 ASCII 最多可表示幾種字元？
3. $10101_2$ 轉十、八、十六進制。
4. $21_{10} = 00010101_2$ 的 1 補數與 2 補數。

### 詳解 {#q-ascii-bases-solution .fold}

**1.** ASCII 的字母編碼是連續的，`B` 就是 `A` 再加 1：1000001 + 1 = **1000010**。

**2.** 每個位元有 0、1 兩種，8 個位元就是 $2\times2\times\cdots\times2 = 2^8 = $ **256** 種。

**3.** $10101_2$：

- 十進制：從右邊數每一位代表 1、2、4、8、16，有 1 的加起來：$16 + 4 + 1 = $ **21**
- 八進制：從右邊每 **3** 位切一組：`10 | 101` → 2 和 5 → **$25_8$**
- 十六進制：從右邊每 **4** 位切一組：`1 | 0101` → 1 和 5 → **$15_{16}$**

**4.** `00010101`：

- 1 的補數：每一位 0 和 1 對調 → **11101010**
- 2 的補數：1 的補數再加 1 → 11101010 + 1 = **11101011**

## 同一串位元的四種解讀 {#q-1011}

$1011_2$ 若分別以無正負號、1 補數、2 補數、符號帶大小表示，十進制各是多少？

### 詳解 {#q-1011-solution .fold}

**思路**：除了無正負號，其他三種都看最左邊的位元決定正負。這裡最左邊是 1，所以都是**負數**，只差在「絕對值怎麼求」。

| 表示法 | 絕對值怎麼求 | 計算 | 值 |
|---|---|---|---|
| 無正負號 | 直接讀，沒有負數 | $8+2+1$ | **11** |
| 符號帶大小 | 後面 3 位直接讀 | 011 = 3 | **−3** |
| 1 的補數 | 全部反轉 | 0100 = 4 | **−4** |
| 2 的補數 | 全部反轉再 +1 | 0100 + 1 = 0101 = 5 | **−5** |

可以在 [[ch1-intro#integer-representation|整數表示法]] 的互動圖點出 1011 對照。

## 1 補數與 2 補數比較 {#q-complement-compare}

比較 1 的補數與 2 的補數的優缺點。

### 詳解 {#q-complement-compare-solution .fold}

重點在「0 有幾種寫法」：

- **1 的補數**：有**兩種零**（0000 是 +0、1111 是 −0）。電腦比大小、做加法時要特別處理，電路比較麻煩。
- **2 的補數**：**只有一種零**（0000），加減法可以用同一套電路，還能多表示一個負數（4 位元可到 −8）。所以電腦普遍用 2 的補數。

## IEEE 754 編碼 {#q-float-encode}

將 $-23.75$ 以 32 位元短浮點表示。

### 詳解 {#q-float-encode-solution .fold}

**思路**：寫成「$1.\text{某某}\times2^{\text{幾次方}}$」，再把正負、次方、某某分三格存。

**步驟 1：轉二進位**

- 整數 23：$16+4+2+1$ → 10111
- 小數 0.75：$0.5 + 0.25$ → .11
- 所以 $23.75 = 10111.11_2$

**步驟 2：移小數點**，讓前面只剩一個 1：小數點往左移 4 位 → $1.011111_2\times2^4$

**步驟 3：填三格**

| 欄位 | 怎麼算 | 結果 |
|---|---|---|
| 符號（1 位） | 負數 | **1** |
| 指數（8 位） | 課本加 128：$4 + 128 = 132$ | **10000100** |
| 假數（23 位） | 「1.」後面的 011111，補 0 到 23 位 | **01111100000000000000000** |

答案：`1 10000100 01111100000000000000000`。

（若用正式 IEEE 754 的偏移 127，指數欄為 $4+127 = 131$ = 10000011。考試照課本用 128。）見 [[ch1-intro#floating-point|實數表示法]]。

## IEEE 754 解碼 {#q-float-decode}

`11000010111011100000000000000000` 是短浮點，對應十進制為何？

### 詳解 {#q-float-decode-solution .fold}

**思路**：編碼倒過來做：先切三格，再還原成科學記號，最後移回小數點。

**步驟 1：切成 1 + 8 + 23 位**：`1 | 10000101 | 11011100000000000000000`

**步驟 2：逐格解讀**

- 符號 1 → 負
- 指數 $10000101_2 = 128 + 4 + 1 = 133$，減掉 128 → $e = 5$
- 假數 1101110…，前面補回省略的「1.」→ $1.110111_2$

**步驟 3：移小數點**：$\times2^5$ 就是小數點往右移 5 位 → $111011.1_2$

**步驟 4：轉十進制**：$111011_2 = 32+16+8+2+1 = 59$，$.1_2 = 0.5$ → **−59.5**

（若用正式偏移 127，$e = 6$，值為 −119。）
