## 遞迴的定義 {#q-definition}

試解釋「遞迴」，並說明撰寫遞迴函數須考量哪些因素。

### 詳解 {#q-definition-solution .fold}

**遞迴**：一個處理程序在處理過程中，又反覆執行同一個處理程序。寫成函數就是「函數自己呼叫自己」，每次處理的問題變小一點，小到能直接回答時就停。

例：$n! = n \times (n-1)!$，算 $n!$ 時用到比較小的 $(n-1)!$，一路縮小到 $1! = 1$。

撰寫時要回答五個問題（以 $n!$ 為例）：

| 要考慮的 | $n!$ 的答案 |
|---|---|
| 函數名稱 | `factorial` |
| 需要的引數與型態 | `long n` |
| 呼叫自己時帶入什麼 | `n-1`（問題變小） |
| 回傳值、怎麼在回傳時呼叫自己 | `return n * factorial(n-1)` |
| 終止條件、終止時回傳什麼 | `n == 1` 時回傳 1 |

最不能漏的是**終止條件**，少了它函數會無限呼叫下去。見 [[ch5-recursion#recursion-tips|撰寫遞迴函數的訣竅]]。

## 遞迴的應用 {#q-applications}

舉出至少 3 個遞迴演算法的應用。

### 詳解 {#q-applications-solution .fold}

共同點：大問題可以拆成「同一種、但比較小」的問題。

| 應用 | 怎麼拆成小問題 |
|---|---|
| $n^m$ | $n^m = n \times n^{m-1}$ |
| $n!$ | $n! = n \times (n-1)!$ |
| 費氏數列 | $F(n) = F(n-1) + F(n-2)$ |
| 河內塔 | 搬 $n$ 個 = 搬 $n-1$ 個 + 搬 1 個 + 再搬 $n-1$ 個 |
| 輾轉相除法求 GCD | $\gcd(a, b) = \gcd(b, a \bmod b)$ |
| 列出所有排列 | 選一個放第 1 位，剩下的再排列 |

見 [[ch5-recursion#ch5-map|本章地圖]]。

## 非遞迴版本 {#q-iterative}

以非遞迴方式寫出：

1. $n$ 的 $m$ 次方
2. $n!$
3. 兩正整數的 GCD

### 詳解 {#q-iterative-solution .fold}

**思路**：遞迴是「從大往小拆，再從小往回算」；迴圈直接「從小往大算」，用一個變數累積結果。

**1. $n^m$**：結果從 1 開始，乘 $m$ 次 $n$。

```c
long power_nr(long n, int m) {
    long r = 1;
    for (int i = 0; i < m; i++) r *= n;
    return r;
}
```

例：$2^4$，`r` 依序是 1 → 2 → 4 → 8 → 16。

**2. $n!$**：結果從 1 開始，乘上 2、3、…、$n$。

```c
long factorial_nr(int n) {
    long r = 1;
    for (int i = 2; i <= n; i++) r *= i;
    return r;
}
```

例：$5!$，`r` 依序是 1 → 2 → 6 → 24 → 120。

**3. GCD**：輾轉相除，每一輪「除數變被除數、餘數變除數」，餘數為 0 時停。

```c
int gcd_nr(int a, int b) {
    while (b != 0) { int r = a % b; a = b; b = r; }
    return a;
}
```

例：`gcd_nr(256, 72)`

| a | b | a % b |
|---|---|---|
| 256 | 72 | 40 |
| 72 | 40 | 32 |
| 40 | 32 | 8 |
| 32 | 8 | 0 |
| 8 | 0 | 停，回傳 **8** |

## 支援遞迴的語言 {#q-languages}

哪些程式語言提供遞迴呼叫？哪些沒有？

### 詳解 {#q-languages-solution .fold}

- **有**：C、C++、Pascal、ALGOL、PL/I
- **沒有**（早期版本）：COBOL、FORTRAN、BASIC

背景：遞迴需要用堆疊在執行時保存每一層呼叫的資料，早期這些語言的每個函數只配置一份固定的記憶體，沒有這種機制，所以不能遞迴。

## 遞迴的優缺點 {#q-pros-cons}

就程式設計的觀點說明遞迴函數的優缺點；哪一種資料結構用來處理遞迴的呼叫和返回？

### 詳解 {#q-pros-cons-solution .fold}

**優點**：程式碼精簡，和數學定義幾乎一樣，好寫好讀。

**缺點**：

- 每次呼叫和返回都要把資料存進、取出堆疊，增加系統負擔。
- 遞迴越深，堆疊上同時存的資料越多，佔用較多記憶體，太深會堆疊溢位。
- 不一定比較快，例如遞迴版費氏數列會重複計算同一個值。
- 不是所有問題都適合遞迴。

**處理呼叫和返回的資料結構**：**堆疊**。理由：最後被呼叫的那一層最先算完返回，正好是後進先出。

見 [[ch5-recursion#recursion-pros-cons|遞迴的優缺點]]、[[ch5-recursion#how-recursion-works|遞迴函數的運作原理]]。
